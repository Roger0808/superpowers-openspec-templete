# 需求调研：AI 并行化与页面多余内容优化

## 1. 现状分析

### 1.1 AI 解析性能瓶颈
当前在 `useClassificationStore.ts` 和 `useLLMParser.ts` 中，调用 MiniMax API 进行内容过滤和章节归类时，使用的是串行的 `for...await` 循环。
当上传的 Excel 行数较多（例如数十个产品组）时，每个请求耗时约 2-5 秒，整体解析时间会随着行数线性增长，导致用户等待时间过长（可能长达数分钟），严重影响体验。

### 1.2 页面内容冗余
在 `HomePage.vue` 中，页面底部包含“核心功能”介绍区块，以及占用了较多垂直空间的 4 步流程指示器。
当用户已经上传文件并进入数据预览或模板选择步骤时，这些引导性内容变得多余，不仅占据屏幕空间，还可能分散用户的注意力，降低沉浸式操作体验。

## 2. 需求目标

### 2.1 提升 AI 解析效率
- **并发请求**：引入并发控制机制，允许多个 LLM 请求同时进行。
- **并发限制**：为避免触发 API 速率限制（Rate Limit）或造成服务不稳定，需要设置最大并发数（如 3 或 5）。
- **进度反馈**：在并发模式下，确保进度条依然能准确反映整体完成进度。

### 2.2 优化 UI 交互体验
- **彻底移除冗余区块**：首页底部的“核心功能”介绍区块占用较多空间且对老用户多余，需直接从代码和界面中彻底删除。
- **组件化重构**：优化 `HomePage.vue` 的代码结构，将庞大的单文件组件（目前超 1100 行）中的特定区块抽取为独立的组件，提高代码可维护性。
- **流程精简**：优化步骤指示器的视觉呈现，使其在小屏幕下更紧凑。

## 3. 约束与边界
- **API 限制**：MiniMax API 有每分钟并发和 Token 限制，并发数不可设置过高，必须具备重试和容错机制。
- **向后兼容**：UI 优化不应改变现有的 4 步操作逻辑。
- **代码规范**：遵循现有的 Vue 3 Composition API 模式，不引入新的重型依赖库。
