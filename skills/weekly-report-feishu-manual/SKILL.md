## 内容格式化规则

1. **项目前缀规则**
   - 原文有前缀就保留原文的前缀，没有就不要自己硬加
   - 不要根据上下文推断项目名添加前缀
   - 只保留原始内容中已有的【】前缀
   - 【变更】、【新增】这两个前缀要去掉
   - 原文中常见的前缀包括但不限于：【统一商品池】、【商品】、【集采】、【售后】、【品控&客服】、【异常单】、【一点通】、【竞价平台】
   - 示例：原文是"【一点通履约费用预估（仓发）——开发中"，就保留【一点通】前缀；原文是"履约费用预估——开发中"，就直接保留，不要自己加上【一点通】或【履约费用】；原文是"【变更】福州海峡银行餐卡对接项目——5.15上线"，就去掉【变更】，变成"福州海峡银行餐卡对接项目——5.15上线"

2. **标题格式规则**
   - 主标题：# 产品周报
   - 本周统计：## 本周统计
   - 业务章节：#### 来福商城与卡册（4个#）

## 过滤规则（与原 Vue程序保持一致）

以下内容会被自动过滤（不出现在周报中）：

1. **无明确上线日期的内容** → 过滤掉
   - 没有上线日期、只说"重新评审"、"已评审待"、"待排期"、"待确认"
   - 必须是**已完成**的内容才记录，必须有明确的上线日期

2. **分类/模块过滤**
   - "其他事项"整个分类过滤掉，不记录

3. **过期已完成内容**
   - 已上线内容只保留**一周内**的（上线日期 ≥ 当前日期 - 7天）
   - 例如：今天是5.16，一周前是5.09，则5.09之前的已上线内容不记录

4. **需求阶段相关**
   - 需求调研、需求分析阶段、需求调研中
   - 需求确认中、需求评审中
   - PRD设计、PRD设计中
   - 方案设计中、售前阶段

5. **时间相关**
   - 下周计划、下周、下月
   - 后续、以后、将来、未来

6. **状态相关**
   - 跟进中、调研中、进行中、处理中
   - 待确认、待讨论、待评审、待排期
   - 暂缓、暂停、停滞

7. **格式相关**
   - @xxx格式的人名标注会被删除
   - 区分两种括号处理：
     - 项目前缀的【】：保留原文已有的【项目名】前缀（如【一点通】、【统一商品池】），但【变更】、【新增】这两个前缀要去掉
     - 其他括号（）、()、《》：括号内的内容会被过滤

## 状态识别（核心规则）

- **已完成** = 真正已经上线（上线日期 ≤ 今天）
  - 例如："5.19上线"、"05.13上线"、"5月12号上线" → 这些都是开发中，因为还没到日期
  - 例如："5月15号上线"、"05.14上线" → 这些是已完成，因为已经到了日期
- **开发中** = 还未上线（上线日期 > 今天，或者是开发中、进行中等状态）
  - 例如："6.4上线"、"5.28上线"、"6月初上线"、"端午节前上线" → 开发中
  - 例如："开发中"、"联调中"、"测试中"、"待上线"、"已发至线上" → 开发中
  - 例如："预计5.21"、"预计5.26" → 开发中
  - 例如："已评审"、"已评审待" → 开发中（还没上线）
- **判断逻辑**：先提取日期，如果日期在未来就是开发中；如果日期在过去就是已完成；如果没有明确日期但有"开发中"等关键词也是开发中
